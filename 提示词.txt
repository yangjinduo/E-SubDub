我想作一款为视频或音频自动生成字幕并配音的软件，如原视频对白为英文，可以生成另一种语言的单语或双语字幕，如果用户想配音，可以将音频中的人声对白清除，克隆为另一种语言的发音，叠加背景音生成新的音轨压制为新的MKV格式的视频。
1. ffmpeg 提取视频音频 → full_audio.wav
2. Demucs/UVR 分离：vocals.wav（对白）、no_vocals.wav（背景）
3. 使用支持说话人区分的ASR模型处理 vocals.wav → JSON：`[{spk, start, end, text}]`，挑选每个 spk 干净长句作为 TTS 音色参考片段（模型计划使用MOSS-Transcribe-Diarize，魔搭社区：https://www.modelscope.cn/models/openmoss/MOSS-Transcribe-Diarize）
4. 用LLM 校对 JSON 内文本，修正识别错误；**保留原有 start/end 时间戳**，因为有些ASR模型断句有问题或识别有错误，可以让大语言模型根据上下方把不完整的文本或错误文本进行修复，如果整段都是无用的文本则需要整段删除，这一步要停止，交给用户人工审核，用户可修改ASR生成的文本及说话人，其中说话人是通过下拉菜单修改。
5. LLM 翻译原文，输出同结构 JSON：`[{spk, start, end, target_text}]`，翻译时约束文本长度。
6. 遍历翻译 JSON：
   - 按 spk 选择对应参考音色，调用 TTS 生成单句中文语音（TTS模型计划使用IndexTTS-2.5，魔搭社区：https://www.modelscope.cn/models/IndexTeam/IndexTTS-2.5）
   - 对比生成音频时长和`end-start`目标时长
   - 使用 time-stretch（不变调）拉伸 / 填充静音，对齐目标时长，对于伸缩比例太大（>1.3x 或 <0.7x）可能已经失真，要作标记，人工听一下是否可以接受，如果效果很差则需要修改翻译词生新生成。
7. 根据json文件和用户的选择生成单语或双语字幕
8. 将所有处理后的 TTS 片段，按时间轴排布，先做 loudnorm 响度统一防止TTS生成的音频音量与原音量不同，然后叠加 no_vocals.wav 混音 → ai_new_audio.wav（完整新配音音轨）
9. ffmpeg 将 ai_new_audio.wav **追加为一条独立音轨**进原 MKV，原有英文音轨保留，不重编码视频

其中第4和5条所需要的LLM大模型我不知该用什么好，你推荐用什么模型呢？LLM大模型要开源、支持本地部署，在满足需求的同时尽量占用磁盘空间小的，用这个可以吗https://modelscope.cn/models/Qwen/Qwen3-4B-GGUF。还能用更小的模型吗？
所使用的模型如果支持CUDA，要自动检查有没有Nvida显卡，如果检测到则自动开启CUDA以加快速度。

UI UX设计：
窗口最上方横向显示各资源的准备状态。包括提取音频所需的FFMPEG，分离人声所需的UVR，音频转文字模型的ASR，校对及翻译所需的大语言模型，声音克隆的TTS模型。资源的功能写在上方，下方写对应的模型，如：上方写“音频转文字”，下方写对应的ASR模型。这样无论是否为专业人员都可以看懂。如果资源没有就续，则要显示“未就绪”。在各资源状态的最右侧有一个设置按钮，点击后可打开各资源对应的状态，已就续的资源要显示文件位置，后面显示删除按钮可以删除资源。未就绪的资源要显示需下载XX，大概占用磁窗空间多少，后方显示下载按钮，直按至资源官网或魔搭社区，点击后弹出窗口选择下载位置，选择后即开始下载，下载时要有进度条提示。

窗口中有一个很大的区域，可以将视频或音频拖入，也可以点击弹窗文件选择窗口去选择文件。
有一个字幕设置区，需要所导入文件的源语言，目标语言，字幕形式可选有单语字幕、双语字幕（目标语言在上）、双语字幕（源语言在上）
有一个配音的开关，默认是开启的，流程如上所述。如果配音关闭，则只生成字幕，生成字幕的流程就简单了，即：1-FFMPEG提取视频的音频，如果导入的就是音频则无所提取。2-将音频交给ASR。3-根据用户所选的字幕形式将ASR的生成结果生成SRT字幕文件。
有一个输出目录设置，将成品文件输出至某位置
