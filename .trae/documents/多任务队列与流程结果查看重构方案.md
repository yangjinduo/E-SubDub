# 多任务队列与流程结果查看重构方案

## Context（背景与目标）

当前应用为单任务模式：主窗口 = 资源状态栏 + 导入区 + 任务设置 + 流程面板 + 开始按钮，所有产物平铺在 `{输出目录}/{视频名}/`。本次重构目标：

1. **顺序多任务队列**：模型（TTS 链路峰值 ~12GB 显存）不支持并行，采用一次只跑一个任务的队列，完成后自动下一个；每个任务可勾选"自动通过人工审核"用于挂机批量。
2. **主窗口重构**为三段：资源状态栏（原样保留）+ 任务列表（序号/任务名称/状态/进度%）+ 底部系统监视栏（CPU/内存/GPU 折线图+百分比，1 秒刷新）。
3. **任务窗口**（主窗口 + 号打开，非模态）：导入区 + 任务设置 + 流程面板 + 开始/停止 + 手动清理按钮。
4. **工作夹按流程分子夹**，成品（SRT/MKV/音频输入时 dubbed.wav）留根目录；分夹顺带解决"人工审核覆盖文本校对结果文件"的缺陷。
5. **10 个流程结果查看窗口**：流程标签完成后可点击打开，含"打开文件夹"按钮。

已确认决策：严格顺序 + 可选自动通过审核；点"开始"才入列（关窗口≠取消任务）；成品在根目录；清理改为手动。

## 关键设计

### 任务类别与命名
- 配音开：`生成配音和单语字幕` / `生成配音和双语字幕`（bilingual_target/bilingual_source 均算双语）；配音关：`单语字幕` / `双语字幕`
- 工作夹名 = `{视频stem}_{任务类别}`（`_sanitize` 处理非法字符）；任务列表名称 = `视频名 + 任务类别`
- 子夹名**固定中文**（音频提取/人声分离/语音识别/文本校对/人工审核/翻译/译文审核/配音生成/混音/封装输出），不进 i18n，避免切换界面语言后断点复用断链

### 工作夹布局（新）
```
{output_dir}/{stem}_{类别}/
  manifest.json            # 增加 "layout": 2 版本字段
  {stem}.{lang}.srt        # 成品（根目录）
  {stem}.dubbed.mkv        # 成品（根目录，视频输入+配音）
  {stem}.dubbed.wav        # 成品（音频输入+配音时从 混音/ 复制）
  音频提取/full_audio.wav
  人声分离/{vocals.wav, no_vocals.wav}
  语音识别/asr.json
  文本校对/corrected.json      # LLM 校对版（pre）
  人工审核/corrected.json      # 审核后版（post）
  翻译/translated.json         # LLM 翻译版（pre）
  译文审核/translated.json     # 审核后版（post）
  配音生成/{refs/, refs/segments/, tts/seg_XXXX.wav, tts.json}
  混音/ai_new_audio.wav
```

### 执行模型
- `TaskManager(QObject)`（主线程，parent=MainWindow）：任务队列 + 当前 runner + `task_id → TaskWindow` 注册表；runner 结束（完成/失败/取消）后 `start_next()`
- 状态机：`queued / running / cancelling / done / failed / cancelled`（等待审核由模态对话框天然体现，不改状态）
- 人工审核分发从 MainWindow 移入 TaskManager；对话框 parent = 该任务的 TaskWindow（若有），标题带任务名；模态期间队列暂停即产品语义
- 自动通过在 runner 内拦截：asr/translation 审核直接落 post 文件并 mark_done；voice 用已挑选 refs 固化；TTS 复听跳过不重生成

### 关键修正（规划阶段验证结论）
- **`app/pipeline/` 全部模块零修改**：extract/separate 等本就接收目标目录/路径参数，只需 Workspace 属性指向子夹
- **resume 加载源配套切换**：翻译输入 = review done ? `人工审核/corrected.json` : `文本校对/corrected.json`；TTS resume = review_translation done ? `译文审核/translated.json` : `翻译/translated.json`；审核 before/after 失效比较改为 pre vs post
- **语言切换**：`_build_ui` 重建 central widget 会销毁 TaskList/SystemMonitor，重建后需从 TaskManager 重新 populate、重启采样线程（响应 destroyed 停线程）；TaskManager parent 为主窗口本体不受影响
- **SystemMonitor**：`psutil.cpu_percent(interval=None)`（否则阻塞 1 秒）；nvidia-smi 后台 QThread（`--query-gpu=utilization.gpu,memory.used,memory.total --format=csv,noheader,nounits`，timeout=2s，连续失败隐藏 GPU 格）

## 风险与对策
- **跨线程信号**：runner(工作线程)→TaskManager 自动 queued connection；runner `finished→deleteLater` 与引用清理在 `start_next` 前完成
- **模态审核期间强杀应用**：runner 阻塞在 threading.Event，closeEvent 不可达——已知限制，保持对话框 reject 必回传 `submit_review(None)`
- **QMediaPlayer 播 MKV**：Windows FFmpeg 后端通常可播，errorOccurred 回退；两个播放器避免同时 play
- **TaskWindow 生命周期**：TaskManager 为唯一注册表；同任务窗口关闭重开用 raise/activate 防重复实例

## 验证方式
- 启动：`venv/Scripts/python app/main.py`
- 场景清单：
  1. + 号建 3 个任务（2 视频 1 音频、混合配音开/关、单语/双语），点开始入列 → 顺序执行，列表状态/进度实时刷新
  2. 勾选自动通过 → 全程无审核弹窗跑完；不勾选 → 审核弹窗标题含任务名，确认后续跑
  3. 各流程完成后点击任务窗口流程标签 → 查看窗口内容正确（分段播放/对照/双播放器/视频播放）
  4. 工作夹结构符合新布局；成品在根目录；文本校对与人工审核两个 json 都在
  5. 运行中取消 → 当前任务取消、自动下一个；失败任务 → 队列继续、可重试断点续跑
  6. 重复添加同视频+同类别+同输出目录 → 拒绝
  7. 系统监视栏 1s 刷新折线/百分比；关闭应用无崩溃（QThread 正确结束）
  8. 切换界面语言 → 主窗口重建后任务列表仍在、已开任务窗口不受影响
